# Exact CPU tapered-evaluation tables

`Tapered` now uses compile-time piece-square tables instead of recomputing
rank, file, center distance, and piece-specific geometry for every occupied
square at every evaluation. The two color tables contain signed white-frame
middlegame/endgame contributions (6 KiB total). Material values, bishop-pair
bonuses, phase weights, the promoted-material phase cap, integer rounding, and
side-to-move orientation are unchanged. The evaluator remains stateless and
keeps its existing unit-struct API.

The crate-local `piece_terms`, `bishop_pair_terms`, and `taper` helpers also let
compact position experiments compute sparse score deltas using the same exact
contributions. Bishop-pair bonuses depend on the complete position's bishop counts.

## Correctness

`benches/support/tapered_reference.rs` preserves the arithmetic implementation
from `c4c9096` independently of the new table generator. Differential tests cover:

- Every piece, color, valid square, and side to move, with separated kings.
- 8,192 dense/sparse positions with both turns, promoted material, bishop pairs,
  and phases above 24.
- Seeded legal playouts from all six `benches/positions.txt` fixtures and each
  reverse unmake, including exact restoration of the original position.

The paired search profile additionally asserts identical scores, best moves,
PVs, completed depths, nodes, and qnodes for every search. All 54 reference/new
pairs in the recorded nine-round run passed. The mate fixture terminates at
its proven mate in depth 1; the other five complete depth 5.

## CPU measurements

AMD Ryzen 5 3600, rustc 1.99.0, normal release profile, no GPU features. Both
evaluators run through the same `Box<dyn Evaluator>` interface inside one binary
with identical search code. Each position gets a fresh searcher and TT. Run
order alternates each round. Processes were pinned to logical CPU 4; the host
was shared with other development work, so these are local measurements rather
than an isolated machine benchmark.

The microbenchmark uses 1,100 positions from deterministic legal playouts of the
six fixtures, 22 million calls per evaluator per round, four rounds. Median
cost was **57.86 ns/call arithmetic versus 24.71 ns/call lookup**, a 2.34x ratio.
All checksums agree. Raw output: [micro.txt](evidence/cpu-eval-20261015/micro.txt).

Median search elapsed time over nine rounds:

| Position | Arithmetic ms | Lookup ms | Arithmetic / lookup |
| --- | ---: | ---: | ---: |
| start | 10.435 | 8.799 | 1.186 |
| kiwipete | 319.686 | 290.100 | 1.102 |
| rook-ending | 3.388 | 3.179 | 1.065 |
| middlegame | 47.699 | 41.311 | 1.155 |
| promotion | 1.085 | 1.041 | 1.042 |
| mate | 0.017 | 0.017 | 0.974 |

The median complete-suite total was **382.002 ms versus 344.426 ms**: 9.8% less
elapsed time, or a 1.109x throughput ratio for identical node counts. The mate
fixture is too short for meaningful timing conclusions. These results establish
an exact CPU runtime improvement on this workload, not a playing-strength gain.
Raw output: [search.txt](evidence/cpu-eval-20261015/search.txt).

Reproduce after building with `cargo build --release --example tapered_profile`:

```sh
taskset -c 4 target/release/examples/tapered_profile micro 20000
taskset -c 4 target/release/examples/tapered_profile search 5 9
```

Validation completed:

```sh
cargo test --release --test eval --test search
cargo clippy --release --lib --tests --examples -- -D warnings
cargo fmt --check
git diff --check
```

The first search-test run lacked the opening-book TSV download and failed the
existing bundled-book test. Rebuilding with `CHEN_OPENINGS_URL=file://...`
pointing to the root checkout's previously fetched, pinned TSVs resolved it;
all 15 evaluator/search tests then passed. No opening-book source or test was
changed. GPU execution and self-play were not performed.
