# Recoverable root-child resource control

`hip-root-retry` is the separate ABI4 control built by `gpu/experiments/root_retry_build.sh`. Set `CHEN_ROOT_RETRY_LIBRARY` to its library and select the UCI/bench backend. The unchanged ABI3 `hip-root-pool` remains the comparison control. All rules, leaf evaluation, history/mate frames, quiescence and root certificates execute on GPU; host only schedules bounded epochs/depths.

A child's q/stack cap now aborts that child without assigning a bound or cancelling other workers. A completed Exact incumbent can authorize retry under `beta=1-incumbent` only when `-32000<beta<=32000` and beta strictly decreases from the failed attempt. Windows stay immutable during each attempt. All entered states, including failed attempts and retries, charge the same total node budget. Completed packets stay immutable; every root certificate rechecks all competitors and earlier canonical ties. Same-window retry is rejected. Node/rule failures and cancellation remain sticky global exits. The default q cap remains32.

Paused and Aborted packets supply no score bound. A separate legal action witness diagnoses the last failed q/stack path and is never emitted as a bound PV. If no pending/paused/admissible retry can change the incumbent, `stalled` returns the prior completed root instead of spinning on empty epochs. Root epochs reject exhaustion. Persistent stacks survive scheduling epochs; a new search reset starts a new identity and clears old history/tasks.

The hardware control passed23 independently exhaustive roots,8 window admissions,6 native controls and7 actual Rust UCI controls. A deliberately capped fixture demonstrates other workers completing, two stricter retries, charged retry work and stable no-retry stagnation. That is mechanism evidence.
