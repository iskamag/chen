# Experimental concurrent root-child pool

`hip-root-pool` is an isolated ABI3 classical control. Root children run in separate GPU workgroups, each with one scalar device DFS worker. Complete legal generation, apply, evaluator, terminal/history checks and quiescence remain on GPU. This distributes independent tasks across CUs; within-child cooperative execution remains future work. It is not the final GPU architecture or a strength claim.

Build `gpu/experiments/root_pool_build.sh gpu/build/libchen_root_pool.so`; build Rust with `cargo build --release --features hip`; set `CHEN_ROOT_POOL_LIBRARY` to that library. UCI `Backend=hip-root-pool` and bench `--backend hip-root-pool` select it. Existing `hip-selective` and `hip-bounded` are unchanged.

Each reset binds authoritative root state, all prior hashes, evaluator, quiescence policy and root epoch. The device classifies the root once and supplies a legal fallback, including zero-time/node requests. Mandatory bootstrap work is outside the search-node budget. No CPU leaf scoring or legality generation occurs during search. Parent hash is inserted exactly once into child history, and child mate-distance frame starts at ply1.

Each depth starts fresh child searches under the same finite horizon. The first epoch gives the previous completed PV one bounded quantum (canonical first move for depth1). Later epochs run all unfinished root children concurrently. Frames, move cursors, intermediate PV and entered-node counts persist across epochs. Pausing neither restarts the tree nor supplies a score bound. Previous-depth score cannot certify a new depth.

An incumbent comes only from a completed child Exact packet, negated to the root frame. New challengers use child window `[-32000, 1-incumbent]`, rejecting parent values strictly below the incumbent while forcing equal-valued candidates to finish Exact. An iteration publishes only with one Exact winner and completed competitor Exact/parent-Upper packets that dominate every alternative; earlier canonical alternatives require strict rejection. Canonical identity here is the unchanged native legal-generation **ordinal**, not a numeric UCI/action encoding. Ascending ordinals select the earliest exact tie. Windows stay immutable after a task starts. All bounds refer to this evaluator/history/main-depth/q policy, not the true game value.

The strict atomic total node budget spans all depths. Unresolved q-cap, stack/rule error or cancellation is sticky and retains the prior completed root. Deadline epochs pause partial stacks; the host checks the overall wall deadline between epochs and retains the last Exact publication. Device epochs share a common wall_clock64 origin and poll every8 DFS transitions; epilogue/retirement/dispatch overhead is measured outside the elapsed cap. There is no global spin barrier. Coherent mapped host cancellation is the only concurrent context operation; serialized reset/begin/advance/destroy calls preserve ownership.

`info string root_pool` and bench `root_pool` report epochs, completed/Exact/Upper/paused child counts, total and iteration nodes, device clock ticks, wall/kernel times and retained scratch. Compare useful completed depth and same-time decisions, not raw node counts across different policies. The first correctness packet uses an independent Python-chess exhaustive traversal with reused exact Tapered arithmetic; it proves neither general playing strength nor compiler/HIP refinement of the Lean certificate model.
